02 / WRITE TIME

Provable from the first draft.

When Claude writes a function outside the subset, the mod names the brick that would apply and the agent rewrites it the provable way. The build-time patch stays nearly empty.

THE LOOP

One function, one turn

Claude writes a function → the PostToolUse hook re-scans → outside the subset? the mod names the brick, Claude rewrites → a spec is proposed → you approve it in the pane → the proof lands → the obligation shows ●.

The Stop hook won’t let Claude declare the task done while anything is failing or stale.

APPROVALS COME FROM PEOPLE

Claude can’t press a mod’s button

The mod refuses approvals coming from the shell, and the PreToolUse guard refuses edits to .rustproof/specs/ and generated Lean, with instructions Claude can act on. Both fail closed.

The PR’s CODEOWNERS review stays the final gate for specs.

03 / THE MOD

Drawn in the terminal and the Desktop app.

Monospace, box-drawing borders, status glyphs, hotkeys shown as 1: Obligations. Elsewhere the hooks still run and the mod falls back to plain transcript lines.

Status band

Above the prompt, only when something needs attention or a run is active. ● 12 ◆ 1 needs review ✕ 1 counterexample ◌ searching 3/5. Digits jump to the right tab.

Proof pane

/proofs opens it, even while Claude is working. Obligations, Needs you, Run, Coverage. Approve a theorem without leaving the terminal.

Live progress

A spinner suffix, compact rows for rustproof tool calls instead of raw JSON, a one-line summary under each answer, toasts when a proof lands.
