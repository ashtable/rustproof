Bricks

Rewrite patterns, with the proof shape included.

A patch is one instance of a brick at one site. Each brick takes a shape of Rust that Aeneas can’t extract and produces one it can, and ships with a proof template: the loop invariant and tactic skeleton for that idiom.

02 / VERIFIED COMPONENTS

rustproof-std: proven once, theorems shipped.

Checked sums, bounded searches, sorted merge. A patch swaps a call to one in, and the proof composes existing lemmas. This is how verified software scales.

checked_sum

rustproof-std

Merge of two sorted slices; theorem: the result is sorted and a permutation of the concatenation.

03 / WHAT A BRICK CAN’T HAVE

An honest limit.

A brick can’t have a general proof that it preserves semantics. Rewrite rules can’t be proven correct without a formal semantics of the source language, and an instance can’t be checked in Lean either, because the “before” is by definition not extractable.

So patches are validated by differential testing and by the person reading the diff. The proofs are about the patched code, which is what ships. This gap affects confidence in the diff, not the correctness of the artifact.
