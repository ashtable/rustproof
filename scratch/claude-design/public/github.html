01 / ON EVERY PR

What the build engineer does.

CHECK RUNS

Per affected crate

Listens to pull_request, push and merge_group. Annotations on the exact Rust line: counterexample inputs, weak specs, changed theorems.

STICKY COMMENT

One comment, updated in place

The spec diff in plain English and Lean, new or changed patches as before/after diffs, counterexamples with the failing input. Markdown only: tables, headings, glyphs. It works without color.

REPAIRS

Proof-only commits as rustproof[bot]

Proof repairs are pushed to the PR branch. Spec changes are opened as suggestions, never pushed.

02 / AUTHORITY

Limited on purpose.

Every surface enforces the same table. Specs live in their own directory under CODEOWNERS, so branch protection enforces this, not policy.

03 / MERGE QUEUE

The combined result is verified before it lands.

Merge-queue commits are immutable, so repairs happen at PR time; the queue only re-verifies. No failing, counterexample or stale obligation ever yields a green check. That rule is itself a proven theorem.

If the merge gate says pass, then no obligation in the run is failing, has a counterexample, or is stale. ●verdict_pass_sound

CI never uses a person’s token. The integration authenticates with its installation token.
