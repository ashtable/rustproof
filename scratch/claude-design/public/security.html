01 / THE GUARANTEES

What “proven” means here.

Proven against the tree that shipped

The build records the hash of the patched tree; proofs are keyed to that hash; release artifacts are stamped with it. “Proven” always means “proven against the tree this was built from.”

No escape hatches

The build fails on sorry, on any axiom outside the approved set (checked with #print axioms), and on any proof that relies on unchecked evaluation.

Specs must have teeth

rustproof mutates the patched Rust and re-checks. A spec that still holds for a mutant is flagged as weak.

The runtime matches the model

Overflow checks stay on in the patched build, so the running code fails exactly where the model says it fails, inside and outside every precondition.

02 / AUTHORITY

Specs live under CODEOWNERS.

The build engineer may write and repair proofs, apply built-in bricks, and change caches and config. It may never change a theorem, apply a custom brick, or move the proof boundary. Branch protection enforces this; agents are refused by hooks that fail closed.

Approvals come from people. Claude can’t press a mod’s button, and the mod refuses approvals from the shell.
03 / IDENTITY

The CLI owns identity.

One login

rustproof login runs browser OAuth (PKCE, loopback redirect) and stores the token in the OS keychain. It covers Claude Code, hooks and the terminal.

MCP borrows it

The plugin’s remote MCP entry asks the CLI for a bearer token and reruns it on a 401, so refresh lives in one place. The server also speaks standard MCP OAuth for other clients.

CI never uses your token

The GitHub integration authenticates with its installation token.

04 / CODE PRIVACY

Where your code goes.

Today

Proof search is GPU-heavy, so v1 runs extraction, search and checking on rustproof cloud. Your code and proofs are processed there for speed, keyed by content hash, and cached as build artifacts.

Later: self-hosted runners

For banks and other sensitive customers: runners on your own machines that pull jobs from the API and send back only results, with proof search on your own GPUs. Leanstral has open weights, so the prover can run where the code is.
