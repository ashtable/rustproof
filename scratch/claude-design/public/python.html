Python inter-op ports

Prove the Python backend through proven Rust.

A Python project goes through the same pipeline with one extra front end. Pure, fully type-hinted spans are ported to Rust in the provable subset, called from the patched Python through a compiled extension, and proven. Inside the approved precondition the proven Rust runs; outside it, the original Python runs unchanged.

Find, port, guard, prove.

From the port onward it is the Rust pipeline: extract, spec, prove, check. The port is validated like a patch: by differential tests and by the person reading the diff.

02 / THE EXAMPLE

A FastAPI billing handler.

◆Proposedprorate_spec

For every amount, days used and period length where the period is at least one day, the days used don’t exceed it, and amount × days used fits in 64 bits, prorate returns at most the amount.

✕What the proof surfaced
Two things the handler never checked: a zero-day period divides by zero, and a large amount over a long period overflows 64 bits. The failure search reports prorate(100, 1, 0) before the spec is proposed, so the precondition arrives with the theorem.
The team decides: reject a zero-day period at the API boundary with a 400, or keep the guarded fallback. Either way, every call inside the precondition runs proven code, and the proof says a customer is never charged more than the full amount.

04 / GUARDS, COST, SHIPPING

Behavior outside the proof is exactly what it was.

Guarded ports

The patch dispatches on the approved precondition, generated as Python from the spec. Inside it the proven Rust runs; outside it the original Python runs unchanged. The guard itself is covered by the differential tests.

The cost of the boundary

A call into Rust costs about 30 nanoseconds plus a few per argument. So candidates are whole loops rather than loop bodies, every port is timed, and a port slower than the Python it replaces is flagged.

What ships

The patched Python tree plus the compiled extension, built by rustproof build with maturin and stamped with the same provenance hash as a Rust project.

This is how rustproof proves its own Python backend: the platform’s authorization and quota decisions are ported, proven, and called through the extension from the deployed API. The parsers, the database and the API around them are shell and are not.
