rustproof cloud

Checking is cheap and local. Finding is expensive and remote.

Checking a proof is deterministic and fast: the Lean kernel plus Lake’s build cache, on your laptop and in hooks. Finding or repairing one is GPU-heavy and parallel, so it runs here.

01 / WHAT RUNS HERE

One proof API behind every surface.

Also exposed as a remote MCP server, so the same endpoint works in Claude Code, as a claude.ai connector, and in other MCP clients.

Check

The Lean kernel with a content-addressed cache of build artifacts. Reruns skip finished work.

Search and repair

Leanstral, through Mistral’s hosted API in v1, run as an agent against the obligation’s Lean project with the kernel as the judge. Many attempts in parallel; bricks ship proof templates so search starts from a skeleton. Self-hosting the open weights comes later.

Counterexamples

Property-based search and fuzzing against the patched Rust. “fib(94) overflows u64” is a bug report. “Proof failed” is not.

Mutation

Mutants of the patched Rust, re-checked. A spec that still holds for a mutant is flagged as a weak spec.

Durable workflows

DBOS on Postgres. A crashed worker resumes from its last step. An obligation parks until its spec is approved, across restarts.

Fan-out with limits

Queues cap GPU prover concurrency. Every external side effect is idempotent, so retries are safe.

03 / ONE PIPELINE EVERYWHERE

The same binary, every runner.

Every step (scan, rank, patch, extract, propose, prove, check, mutate, counterexample, build, test, report) is idempotent and keyed by content hash. Workers call the open-source CLI, so there is one implementation of every primitive. Nobody needs Postgres to use rustproof.
